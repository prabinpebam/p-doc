# Line behaviour contract

Status: draft contract, 2026-10-30. Docs only; no implementation is authorised by this file. Traces to P1/P3/P4 → J3/J15 → U115 (insert a line or an arrow, set its endpoints, stroke and end styles, and place it like any other shape), U114.P1–P3 and flows DP1–DP4 in [spec](../product/spec.md) ("Rectangle document placement addendum"), applied to the line by the permanent process rule ("rectangle first, then polygon, star, line, arrow"). Since the spec's [shape generalisation decisions](../product/spec.md#shape-generalisation-decisions-2026-10-30-cd-63a0) (SG1, SG3; 2026-10-30), U114.P1–P3 and DP1–DP4 name every shape, and U115 is the line's own user-can statement: a row whose Trace reads "U114" serves **U115** (lines carry no text, so U114's "text-bearing" does not apply); placement rows trace to U114.P1–P3 as written. No row's behaviour changes.

**Process.** Same as the [rectangle contract](rectangle-behaviour-contract.md): (1) this contract; (2) an independent completeness critic; (3) one automated test per in-scope row (`T-LN-…`), done only at 100 % passing; (4) a contract-blind adversarial review, whose findings become rows; (5) the owner. Builds wait for the owner's rectangle verdict. Out-of-scope rows are listed on purpose with a reason.

**Reuse.** Where a line behaves exactly like the rectangle, the row says so and cites the RC row; the RC row's full wording, examples and sources apply with "line" for "rectangle". Each such row still has its own test ID, so the line build is tested row for row. Line-specific rows are written out in full.

**Columns.** *Trace* is the spec chain the row serves. *Scope* is `in` with its reason code, or `out` (section 13) with the reason in the row. Reason codes: **R-F** Figma behaviour for shape editing (precedence 3); **R-W** Word behaviour for placement, text flow and undo (precedence 2); **R-O** an owner decision (precedence 1); **R-C** a contract decision needed for completeness, safety or access (precedence 4, reason in the Source cell).

## Precedence

1. Owner decisions in the spec: inline default and no X/Y for inline (OD-INL), no on-canvas labels (OD-LBL), deselect outside the page (OD-DES), the permanent number-field rule (OD-NUM), rotated shapes wrap around their axis-aligned bounding box (OD-ROT), the process rule and the testing-safety rule.
2. Microsoft Word, for document placement, text flow and undo.
3. Figma, for shape editing, the pane and the canvas (current help.figma.com pages).
4. Contract decisions (**CD**) where none of the above says anything, each with its reason, for the critic to challenge.

| LN-CD-02 | Endpoint drag rounding, by modifier: **plain** — the dragged endpoint lands on whole page px, W and Rotation carry fractions (2 decimals); **Shift** — the snapped angle and a whole-px length win, the dragged endpoint may hold a fraction; **Alt** — the dragged endpoint lands on whole page px and the other is 2 × centre − dragged (a fraction only if the centre has one); **Shift+Alt** — the snapped angle and a whole-px **half**-length about the fixed centre win, both endpoints may hold fractions. | Same rounding rule as rectangle resize ([RC-CLK-39](rectangle-behaviour-contract.md)); length and angle of a whole-px segment are rarely whole. |

## Conflicts resolved in this contract

1. Figma's stroke page says lines default to **center** and its table says lines have **no Position**; the owner's S9 arrow pane shows a Position select reading Inside. The documented table wins (precedence 3 over an observed screenshot): no Position select, always centred (LN-COL-10, LN-OS-04).
2. Word's Tight follows a shape's outline ([W-WRAP](https://support.microsoft.com/en-us/office/wrap-text-around-a-picture-in-word-bdbbe1fe-c089-4b5c-b85c-43997da64a12)), so a diagonal line's text would fill the triangles beside it. The owner's OD-ROT (rotated shapes wrap around their axis-aligned bounding box plus the distances) outranks Word (precedence 1 over 2), and RC-WP-09 already applies it to a rotated rectangle's Tight. So Tight on a diagonal line equals Square (LN-WP-09) and outline-following Tight is out of scope (LN-OS-39). The first draft had it the other way round (critic r1 G1, coordinator decision).
3. Figma documents **Round** as the default cap; in common use Figma's Line tool may show None. The help page is the citable source, so Round is the default (LN-COL-01, LN-BTN-16/17).
4. Rectangle X/Y is the unrotated top-left and does not change on rotate ([RC-CLK-41](rectangle-behaviour-contract.md)); a line's X/Y is its start point and does change (LN-CD-01, LN-CLK-34).
5. Word draws lines floating (In Front of Text) by dragging; OD-INL makes every inserted shape inline, and drawing is out (LN-OS-01).
6. Figma's `157 × 0` dimension badge (S9) is dropped by OD-LBL (LN-FB-07).
7. Figma removes a line's stroke with −; here only the eye hides it (LN-CD-05).
8. Lines and arrows: the first draft left arrowhead caps to the arrow contract (old LN-CD-06, LN-OS-03). Coordinator decision CD-SH-10 19:05 makes them one object kind with the full Figma cap list in both contracts; the shared choices of CD-SH-11 (insert, crosshair, swap disabled when equal, no hover preview, weight 0–100, anchor under the bounding-box top), CD-SH-12 (dashes on the shaft only), CD-SH-13 ("Rotation", dark-neutral default colour) and CD-SH-14 (Tight = bounding box) already match this contract.
9. Export and import: the [arrow contract](arrow-behaviour-contract.md) refuses export of any document with lines or arrows (AR-INS-13), names left-out Word lines and arrows "shapes" on import (AR-INS-12) and defers real shape export and import (AR-OS-27). Because lines and arrows are one object kind (CD-SH-10), the line contract mirrors all three (LN-PER-05, LN-PER-04, LN-OS-40) with the same messages, order, fixtures, CLI strings and exit code; the arrow rows carry the same one-label-per-category sentence and line + arrow fixture (AR-INS-12, critic r5 R5-02, R5-03); the refusal and the importer label change are built once, in whichever of the line and arrow stages lands first.
