# Ellipse behaviour contract

Status: draft contract, 2026-10-30. Docs only; no implementation is authorised by this file. Traces to P1/P3/P4 → J3/J15 → U114 (draw, resize and format text-bearing shapes), U114.P1–P3 and flows DP1–DP4 in [spec](../product/spec.md) ("Rectangle document placement addendum", whose placement, number-field, process and testing-safety rules apply to every shape; "Behavior reference decisions (2026-10-30)", **BR5 — Circle / ellipse aspect lock**). Spec references name the section at HEAD `bed8c82` (the spec is unchanged at `9095350`). Builds for this shape wait for the owner's verdict on the rectangle.

**Trace.** Since the spec's [shape generalisation decisions](../product/spec.md#shape-generalisation-decisions-2026-10-30-cd-63a0) (SG1, 2026-10-30, coordinator batch CD-63A0; in the spec working copy, not yet committed at the time of writing), U114.P1–P3 and DP1–DP4 name every shape, so EL placement rows trace to them directly (the polygon's and star's wording; critic r2 E2-08).

**Process** (spec, "Behaviour contract process — PERMANENT rule", 14:34): (1) **contract** (this file); (2) **independent completeness critic**; (3) **build and test 1:1**: one automated test per in-scope row, done only at 100 %; (4) **contract-blind adversarial review** plus an independent visual check; (5) **owner**. Out-of-scope rows are listed on purpose with a reason; nothing may be silently absent. Every test follows "Testing safety — PERMANENT rule" (15:50): headless, a fresh temporary profile, no visible window, no OS cursor or focus taken, the pre-flight window check recorded with the run.

**Owner amendment (ROOT 22:02, 2026-10-30), not yet folded into rows.** In **Tight**, text wraps around the ellipse's actual outline, rotated or not, and one **Distance from text** field replaces the side distances (spec [OW1–OW8](../product/spec.md#outline-wrap-amendment-owner-root-2202-2026-10-30), U114.P5). Where they conflict, the amendment wins over the rotated-Tight parts of EL-CD-07 and EL-WP-04 and over EL-OS-07 (now required). Square, Top and bottom and In line keep their rows. Rows and tests are rewritten only after the owner's verdict on the static preview (DoD OW-ELL-1); existing evidence predates the amendment and is not proof of it.

**How this contract reuses the rectangle contract.** An ellipse is the rectangle's object with an elliptical outline and **no corners**: same selection, pane, number fields, fill and stroke, Word placement, undo and keyboard rules. So, exactly as the [polygon](polygon-behaviour-contract.md) and [star](star-behaviour-contract.md) contracts do:

- **Inherited rows.** Each section lists the RC-IDs of [rectangle-behaviour-contract.md](rectangle-behaviour-contract.md) that apply **unchanged**, reading "rectangle" as "ellipse", "Insert > Rectangle" as "Insert > Ellipse", "Rectangle N" as "Ellipse N" and "A rectangle can't go inside another rectangle" as "**An ellipse can't go inside another shape**" (the star's ST-SEL-02(b) pattern). **"Another rectangle" means any shape.** Where an inherited row speaks of another rectangle, or of a rectangle's own text, as a **container** or as **the other object** (RC-SEL-21(b) "caret or selection inside a rectangle's own text", RC-WP-05 "dropping inside another rectangle's text", RC-SEL-06 "another floating rectangle", RC-NF-12 "click another rectangle", RC-SEL-22 "one or more rectangles shape-selected"), it reads "a shape of **any kind**" (rectangle, ellipse, polygon or star) and "a shape's own text"; "rectangle" becomes "ellipse" only where the row speaks of the ellipse itself. So no ellipse is ever nested in any shape: T-EL-RC-SEL-21 (b) runs with the caret in a rectangle's, a polygon's, a star's and another ellipse's text (each: Insert > Ellipse and the command disabled with "An ellipse can't go inside another shape"), and T-EL-RC-WP-05 drops an inline ellipse onto each of those four kinds' text (each refused; the ellipse returns). The reverse (another kind inserted or dropped into an ellipse's text) is EL-SEL-10. Lines and arrows are shapes too (spec SG1); their insertion into a shape's text is refused by their own rows (LN-SEL-19(b), LN-WP-05, AR-INS-06), which EL-SEL-10 refers to rather than restates (critic r2 E2-07). Each inherited row is still built and tested for the ellipse: its test ID is `T-EL-` + the RC-ID (e.g. `T-EL-RC-CLK-21`), so it never collides with an EL row's test (`T-EL-CLK-01`). An inherited out-of-scope row stays out for the ellipse for the same reason. **Rectangle base: commit `9095350`** (`docs/research/rectangle-behaviour-contract.md`, critic rounds r8–r14 folded in, r14 clean; 404 row IDs, 358 in scope: RC-PTR 21, RC-CLK 42, RC-SEL 22, RC-CAN 40, RC-NF 34, RC-PL 10, RC-FLD 25, RC-BTN 28, RC-COL 23, RC-WP 40, RC-UR 38, RC-KB 23, RC-FB 15, RC-OS 43; decisions CD-01…CD-14 and CD-63A0-01). Each inherited row is read **as worded at `9095350`**. (The first draft inherited from the working copy SHA-256 `7FB4D05E3DBF…`, 403 IDs; the resync is in the changelog.) A row added to the rectangle contract after `9095350` is inherited by default unless the critic or an EL row says otherwise.
- **Page px.** Every px value in this contract (EL rows, EL-CDs, worked values and tests) is a **page px** as the rectangle's CD-03 defines it: 1 CSS px at 100 % zoom = 1/96 in; a US Letter page is 816 × 1056 page px with a 624 page px column at 1 in margins; a build or harness that keeps another internal unit converts by 816 / internal page width before applying a px rule or asserting it; the pane shows, clamps and rounds in page px.
- **Reading rule R2 (frame for anchor and gap rules).** Where an inherited row speaks of the rectangle's **bounding box** or **rotated bounding box** to place, anchor or measure it (RC-WP-13 "top of the rotated bounding box", RC-CAN-01, RC-WP-14, RC-WP-16, RC-WP-17, RC-WP-20, RC-WP-22 Y measured to the box's top, RC-SEL-05, RC-SEL-14, RC-SEL-22, RC-BTN-28), it means the ellipse's **frame** (unrotated) or the axis-aligned box of the **rotated frame** (EL-CD-02, EL-CD-07), never the outline. Where an inherited row speaks of the **wrap area** beside which text flows (RC-WP-38), it is the frame (or rotated frame box) plus the distances for every mode except **unrotated Tight**, where it is EL-WP-03's per-line interval; so T-EL-RC-WP-38 case (d) reads "Tight, W 300 × H 200 **ellipse**, X 304 (20 page px right gap beside the frame's widest lines) → no word in the right gap on any spanned line whose computed EL-WP-03 gap is under 48 − 0.01 page px", and the radius in that case has nothing to act on (R1). "Computed EL-WP-03 gap" means EL-WP-03's interval as corrected in critic round r1 (the stroked, distance-grown outline); case (d) has no stroke and distances 0, so its values are unchanged. Cases (a)–(c) run unchanged on the ellipse's frame (Square). The assertion is one-directional (the harness's word-rect line extent is never taller than the layout's band, so it never demands an empty gap the engine may fill); the positive half (a gap ≥ 48 − 0.01 page px receives a run) is T-EL-WP-03's.
- **Reading rule R1 (no corners, no dots).** An ellipse has no corner radius and no on-canvas dot (EL-CD-04). In these inherited rows the clauses about radius dots, radii or corner fields **have nothing to act on** and are not tested; every other clause of the row applies and is tested: RC-CLK-04 (double-click on a handle or rotation zone), RC-CLK-17 (Esc during a move, resize, rotate or inline drag), RC-CLK-37 (handles, rotation zone, anchor marker), RC-SEL-04 (no W × H, X/Y or angle badge), RC-SEL-06 (outline only, no handles), RC-NF-32 (the canvas-radius sentence), RC-BTN-26 (the Independent corners sentence; Lock aspect ratio Mixed applies), RC-BTN-27 (the corner-radius and independent-corners icons are not rendered for an ellipse; every other icon rule applies), RC-WP-14 (size, rotation and paint kept), RC-WP-36 (chrome: outline, 8 handles, rotate zones), RC-KB-15 (chrome, handles, focus), RC-KB-20 (never resizes, flips, nudges …), RC-KB-21 (chrome tokens), RC-OS-19 (combined-bounds resize or rotate).
- **Replaced rows.** Where the ellipse differs, the RC row is **not** inherited; an EL row says so in its Source column ("replaces RC-…") and is the only contract for it.
- **Not applicable.** RC rows with no ellipse counterpart (corner radius, radius dots, independent corners) are listed in their section with the EL decision that explains why.
- **EL rows** are written in full. Columns as the polygon contract: ID, control/element, input/state, expected behaviour (observable), source, test ID, scope, **Trace** (the spec user-can or flow it serves, by section name). "in" means built and tested in this slice; "out" rows give their reason in the behaviour column.

No EL row adds a cross-page anchoring case.

**CD-63A0-02 (driving side and re-capture of a kept ratio, coordinator decision 2026-10-30), in full.** (a) On a ratio-kept **corner** drag (lock on, or Shift held), the axis whose **relative** change \|new/start − 1\| is larger drives, with new W′ and H′ the signed free-resize sizes the pointer gives from the start geometry (from the centre with Alt); a tie takes **width**; the other side is derived from the **stored** ratio (locked) or the drag's start W:H (unlocked with Shift), never from the previous rounded size. (b) **Shift+Ctrl** on a locked shape keeps the **stored** ratio, as a plain locked drag does. (c) The stored ratio is re-captured from the final W:H only when the pointer is released with **Ctrl held** (and Shift not held) and the lock on; Ctrl pressed and released before the pointer is released re-captures nothing. (d) Edge handles keep RC-CLK-26. **Reason:** F-LOCK says only that Shift keeps and Ctrl "temporarily" frees the ratio while held during a canvas resize; it names no driving side and nothing at release, and no other shape contract decides it. A relative change follows the axis the pointer moved most relative to the shape, so the shape stays under the pointer whether it grows, shrinks or flips ("the larger scale factor" would pick the side that changes less when shrinking: locked 200 × 120 dragged by (−100, −10) would give 183 × 110 instead of 100 × 60); tying to width and deriving from the stored ratio make the result deterministic and drift-free; reading the keys at release matches F-LOCK's "temporarily … by holding". Recorded here in full because the coordinator gave it in its brief; proposal (4) asks for it in `coordinator-shared-decisions-1905.md` for every shape with Lock aspect ratio. Applied in EL-CD-08, EL-CLK-05/06/07, EL-CAN-06 and EL-UR-01.

| EL-CD-08 | **Aspect lock (BR5).** Lock aspect ratio is a stored per-ellipse value, **off** on insert and when missing, `null` or not a boolean in a file. Turning it on **captures the current W:H exactly** (5:3 for 200 × 120, 1:1 for a circle) without changing W or H; the captured ratio is **stored in the file with the lock** (as RC-FLD-08 keeps it exactly, never recomputed from 2-decimal W and H); turning it off discards the ratio and changes nothing else. While on, every canvas resize and every W or H edit keeps that ratio (RC-BTN-11, RC-FLD-06…08). **No ratio drift** (critic r2 E2-01): every ratio-kept change (a locked canvas resize, a Shift resize, a locked W or H edit) derives the other side **on every step** from the driving side's new value and the **stored ratio** (locked) or the **drag's start W:H** (unlocked, Shift held): derived = driving × or ÷ ratio, rounded only in that derived value (whole page px on the canvas, RC-CLK-39; 2 decimals in a field, RC-NF-32), never computed from the previous rounded size, and such a change **never re-captures** the ratio. The stored ratio is re-captured only when the lock turns on and when a **Ctrl-freed** resize ends with the lock on, that is, the pointer is released with **Ctrl held and Shift not held** (the ratio free at release; its final W:H becomes the stored ratio); a resize where Ctrl was pressed and released before the pointer is released ends ratio-kept and re-captures nothing (CD-63A0-02, critic r3 E3-03); this is how this contract reads RC-FLD-08's "set by a canvas resize". Undo and redo restore the ratio stored with that state; they never re-capture it from W:H. Example: locked 200 × 120 (5:3), three right-edge drags of +1 → **201 × 121** (120.6), **202 × 121** (121.2), **203 × 122** (121.8); the stored ratio stays exactly 5:3. Canvas modifiers (F-LOCK): **Shift** keeps the current ratio while held when unlocked; **Ctrl** frees the ratio while held when locked; **Shift+Ctrl** together keep the ratio (Shift asks for the ratio explicitly; Ctrl only lifts the stored lock), and on a **locked** ellipse the ratio kept is the **stored** ratio, as for a plain locked drag, not the drag's start W:H (critic r3 E3-02: locked 201 × 121 with stored 5:3, Shift+Ctrl right edge to 300 → **300 × 180**, not 300 × 181 from 201:121); pressing or releasing either key mid-drag takes effect at the next pointer move, measured from the drag's start geometry; modifiers never change the stored lock. **Driving side** on a ratio-kept **corner** drag (locked, or Shift held), CD-63A0-02: from the start geometry, the free-resize W′ and H′ the pointer would give (signed, so a crossed edge is negative; with Alt, from the centre) are turned into **relative changes** \|W′/W₀ − 1\| and \|H′/H₀ − 1\|; the side whose relative change is **larger** drives and the other side is derived from the ratio (the stored ratio when locked, the drag's start W:H when unlocked with Shift); a tie takes W; the dragged edges then land on whole page px and the derived side is rounded half away from zero (RC-CLK-39). ## Conflicts resolved in this contract

The rectangle contract's conflicts apply unchanged, and the polygon's conflicts 4, 7, 8, 10(d)(e), 11 and 13 apply where they speak of closed shapes. Ellipse-specific:

1. **Arcs.** Figma's ellipse carries arc, start and ratio handles (F-ARC); the contract leaves them out with five reasons (EL-CD-03) and states the absence as rows (EL-PTR-03, EL-OS-03…06, EL-FB-01).
2. **Circle as its own insert.** BR-EL has "Insert circle"; Figma has one Ellipse tool (F-EL) and the API defines a circle as width == height (F-API-EL), so there is one insert (EL-CD-01, EL-OS-08) and old circle files open as ellipses (EL-CAN-10).
3. **Default size.** BR-EL inserts 240 × 144 (circle 240 × 240); CD-SH-03 sets 200 × 120 for every closed shape (EL-CD-01).
4. **Lock modifiers.** BR-EL's canvas resize keeps the ratio when locked **or** Shift is held and has no Control override (spec BR5 ledger: "Pointer code uses stored lock OR Shift, without Control override"); BR5 adopts Figma's Control-disable, so Ctrl frees a locked ratio (EL-CD-08, EL-CLK-05). The Shift+Ctrl combination and mid-drag changes are decided here (Shift wins; next pointer move).
5. **Lock refusals.** BR-EL refuses a locked W/H that cannot keep the ratio ("That size cannot preserve the aspect ratio here. Use another size."); RC-FLD-08 never refuses: both sides clamp proportionally (EL-FLD-02).
6. **Text area.** BR-EL centres text in a grid whose middle cell is 1/1.42 of W and H (≈ W/√2 − 0.3 %) and lets the text grow the ellipse (auto-height); the contract uses the exact W/√2 × H/√2 rectangle (CD-SH-07), top-anchored RC-CAN-40 margins, fixed H with visible overflow (BR2, RC-CAN-38/39) (EL-CD-06).
7. **Square versus Tight.** For an ellipse the frame and the outline differ, so both modes are built honestly (EL-CD-07, EL-WP-02/03), as spec DP2 requires.
8. **Rotated circle wrap.** A rotated circle's outline is unchanged, but OD-ROT wraps every rotated shape on its rotated frame's box; the owner's rule wins (EL-WP-04) and the refinement is only proposed (EL-OS-07).
9. **Damaged lock.** BR-EL throws "Aspect lock is invalid. Restore a valid document version." on a non-boolean lock; the contract opens it as off (EL-CD-10).
10. **Mixed selections.** CD-SH-05 lists shared fields for polygon + star; with an ellipse, Corner radius is hidden as Count and Ratio are, since the ellipse has none of them (EL-CD-09).
