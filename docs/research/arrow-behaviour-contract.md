# Arrow behaviour contract

Status: draft contract, 2026-10-30. Docs only; no implementation is authorised by this file. Traces to P1/P3/P4 → J3/J15 → U114, U114.P1–P3 and flows DP1–DP4 in [spec](../product/spec.md) ("Rectangle document placement addendum", applied to every shape by the process rule), the permanent number-field rule and the permanent behaviour-contract process rule (which names "polygon, star, line, arrow"). The spec has no arrow-specific user-can statement yet; U114 reads "text-bearing shapes", and an arrow carries no text. Rows trace to U114 as the shape capability and flag that gap (open question OQ-1) rather than invent an ID.

**Process.** Same as the [rectangle contract](rectangle-behaviour-contract.md): (1) **contract** (this file); (2) **independent completeness critic**; (3) **build and test 1:1**, one automated test per in-scope row with the row's test ID, done only at 100 % passing; (4) **contract-blind adversarial review** plus an independent visual check; (5) **owner**. Builds of this contract wait for the owner's verdict on the rectangle. Out-of-scope rows are listed on purpose with a reason; nothing may be silently absent.

**Relation to the line contract.** Line and arrow are **one object kind**, a two-point line (coordinator decision CD-SH-10 19:05, AR-CD-17): it is called "Arrow" when either end has an arrowhead style and "Line" otherwise. Everything a plain line does is owned by [line-behaviour-contract.md](line-behaviour-contract.md) (`LN-` IDs; **committed** in `0d72adc`, sha256 8c608f64…, 380 rows, re-read 2026-10-30 19:08 for round 4). Every arrow row cites its `LN-` counterpart (mapping from critic round 1). **Inheritance rule:** every in-scope LN row that this file does not override or list as a conflict applies to the arrow unchanged, with "arrow" for "line"; the ones with no arrow row of their own are listed in section 16 with their own `T-AR-LN-` tests. Every arrow-specific behaviour (the Arrow command, all eight end styles, swap, cap scaling, endpoint handles, Shift snapping, Length and Rotation, hit-testing, the pane and placement) is written out in full here.

**Columns.** As the rectangle contract, plus **Trace** (the spec.md link each row serves). Test IDs are `T-AR-<section>-<nn>` and unique across this file.

## Contract decisions to challenge (CD)

| CD | Decision | Reason |
| --- | --- | --- |
| AR-CD-01 | **Model.** An arrow is two endpoints (start, end) in page px plus a stroke (colour, opacity, weight) and a cap style per end. No fill, no text, no H, no corner radius. Length = distance start→end; Rotation = direction start→end. | F-SHAPE (drawn by two points), F-STROKE (endpoint caps on two-point paths); S9 shows W 157, H 0. |
| AR-CD-02 | **Insert, not draw.** Insert > Shapes > Arrow (and the toolbar Shapes menu and command search) inserts an arrow **inline at the caret**; drawing with a drag and the Shift+L shortcut are out (AR-OS-01, AR-OS-02). | OD-INL wins over Figma's drag tool (precedence 1); consistent with RC-OS-33. Shift+L would type a capital L in the text, the document's main input. |
| AR-CD-03 | **Default on insert:** inline; start (0, 0) to end (200, 0) (W 200 px, Rotation 0°, pointing right, as the line's LN-CD-07 length); stroke weight 1 px, centre, Solid; stroke colour = the **dark-neutral token's light-theme value stored as a fixed colour** (RC-COL-13, LN-COL-01; coordinator decision CD-SH-13 19:05); stroke opacity 100 %; layer opacity 100 %; Start point **None**, End point **Line arrow**. | Figma's default weight is 1 and the Arrow tool's documented purpose is a one-sided arrow (F-SHAPE); which end carries the tip is not stated, so the end is the tip (the natural reading of "draw an arrow"). The line's Round default (LN-COL-01) is not used: an arrow inserted with no arrowhead would be a line (AR-CD-17). Same colour as a fresh line and rectangle. |
| AR-CD-04 | **Cap geometry scales with weight** `w`. Head size `h = max(4w, 6 px)` for w > 0; **h = 0 at w = 0** (AR-CD-10). **Shaft set-back** s(style), measured from the endpoint inward along the shaft, defines where the shaft (solid or dashed) is drawn: **None 0; Round 0; Square 0** (the cap is drawn solid beyond the endpoint); **Line arrow 0** (the shaft runs to the tip; the arms are separate solid strokes); **Triangle arrow h; Reversed triangle h; Circle arrow h/2; Diamond arrow h/2**. Shaft length **L = W − s(start) − s(end)**; if L ≤ 0 no shaft (and no dashes) is drawn and the heads are drawn as AR-CAP-15. None: the line ends flat at the endpoint. Round: a half-disc of radius w/2 beyond the endpoint. Square: a w/2 extension beyond the endpoint, flat. Line arrow: two strokes of weight w from the endpoint back at ±45° to the line, each `h` long, joined at the tip with a miter. Triangle arrow: a filled triangle in the stroke paint, tip on the endpoint, length `h`, base width `h`; the line stops at its base. Reversed triangle: the same triangle with its base on the endpoint and its tip pointing inward along the line. Circle arrow: a filled disc of diameter `h` centred on the endpoint. Diamond arrow: a filled square turned 45°, diagonal `h`, centred on the endpoint. Endpoints are never moved by a cap. | F-VN and F-STROKE give the shapes, that Line arrow uses the path's weight and that its arms cannot be resized, and that Round/Square add half the weight; neither page gives head sizes, so they scale with weight (as Figma's do visibly) with a 6 px floor so a 1 px arrow still reads as an arrow. |
| AR-CD-05 | **Shift snaps the angle to 45° steps** (0, ±45, ±90, ±135, 180) while dragging an endpoint, measured about the fixed end. | W-LINE (Shift for horizontal or vertical) and Figma's Shift constraint family (F-SHAPE, F-ARPD); 45° includes Word's horizontal/vertical and the diagonals people draw arrows at. Not documented for lines on any fetched page. |
| AR-CD-06 | **Hit area** is the drawn ink (shaft, caps, heads, arms) widened to at least **max(4 screen px, half the on-screen weight)** from the centreline (LN-SEL-22), measured in screen px at every zoom. Endpoint handle targets are **10 × 10 screen px** and win over the body, objects beneath and text (LN-SEL-26). The rotation zone (LN-PTR-06, 16 screen px) starts **beyond the head's ink**: a press on a head or arm selects or moves the arrow, never rotates it. Clicks inside the bounding box but outside the band fall through to what is beneath. | No source states hit-testing; same rule as the line so a mixed selection behaves one way; heads are part of the object people aim at. |
| AR-CD-07 | **Length edits keep the start point**; Rotation edits rotate about the midpoint. | F-ARPD: W changes from the "original top-left" (for a line, its start); rotation is about the centre. |
| AR-CD-08 | **X / Y (floating only) are the start point** relative to the chosen references; stroke and caps are not included. | F-ARPD (X/Y at the original top-left; for an unrotated line that is the start) and F-STROKE (weight not in dimensions); S9 shows X/Y with W 157, H 0. |
| AR-CD-09 | **Placement and wrap use the drawn ink box** (shaft, stroke, caps and heads; the same box the line calls "the bounding box of the visible stroke", LN-WP-09, and the "bounding box" its anchor rule uses, LN-CAN-01): inline it occupies that box on the baseline; Square **and Tight** use that axis-aligned box plus distances for any rotation (coordinator decision CD-SH-14 19:05, OD-ROT; outline-following Tight is out, AR-OS-29); alignment buttons align the **endpoint box** (as Figma's dimensions). | OD-ROT makes the axis-aligned rotated bounding box the wrap shape for rotated shapes; the ink box keeps text from overprinting an arrowhead. Alignment follows Figma's dimensions (F-STROKE). |
| AR-CD-10 | **Stroke is mandatory** (no "−"; the eye hides it); **weight 0…100 px** as the line (LN-FLD-11; coordinator decision CD-SH-11 19:05). At weight 0 nothing is drawn, heads included (h = 0), and the object stays selectable by the minimum hit band and Document objects. | F-STROKE allows weight 0; one range for the one object kind keeps Mixed edits on a line + arrow selection simple. |
| AR-CD-11 | **No stroke Position control**; arrows are always centre stroke. | F-STROKE: lines are centre and the table marks Position ✕ for Lines and Arrows. S9 shows "Position Inside"; the documented table wins over one screenshot (conflict 2). |
| AR-CD-12 | **Swap** ("Swap endpoint caps", as LN-BTN-18 / LN-KB-12) exchanges the Start point and End point styles only; endpoints, W, Rotation, X and Y stay. Disabled with the reason "Both ends already match" when they match (CD-SH-11). | S9 shows a swap control between the two cap menus; F-STROKE says each end is set independently. Swapping geometry would move X/Y, which no source asks for. |
| AR-CD-13 | **Endpoint handles** are 8 px squares (shape-handle tokens; 10 × 10 screen px target, AR-CD-06) at each endpoint; no bounding box, resize handles or radius dots; the line's rotation zone beyond each endpoint's ink applies (AR-CLK-23). Cursor on a handle: **crosshair** at every angle (LN-PTR-05; coordinator decision CD-SH-11 19:05). | S9 shows square endpoint handles and no bounding box; one cursor for the one object kind. |
| AR-CD-14 | **Minimum length 1 px.** An endpoint dragged or typed onto the other end stops 1 px short along the last direction; the arrow is never zero-length. Dragging past the other end simply reverses the direction (no clamp). | A zero-length arrow has no direction for its caps (branch proof also refuses it); a flip-through is what a free endpoint naturally does. |
| AR-CD-15 | **Enter and double-click** on an arrow do nothing beyond selecting it (no text, no vector edit mode). | F-VEDIT's vector edit mode is out (AR-OS-07); an arrow has no text (AR-CD-01). |
| AR-CD-16 | **Endpoint handles are keyboard-focusable** (Tab from the selected arrow: Start point, then End point, then the pane); arrow keys move the focused endpoint 1 px, Shift 10 px; Esc returns focus to the arrow. | WCAG 2.1.1: the endpoint drag must have a keyboard equivalent; mirrors the radius-dot keyboard model (RC-CAN-20) with the shape's nudge steps (F-ARPD 1 / 10). |
| AR-CD-17 | **One two-point object kind** (coordinator decision CD-SH-10 19:05): lines and arrows are the same object; the kind and name follow **LN-SEL-30** (Arrow while either end has an arrowhead style, else Line; number kept; updates live). The Arrow command inserts that object with Start None / End Line arrow. Mixed selections: LN-SEL-31; header: LN-SEL-32; selects: LN-BTN-16/17. This file defines only what is arrow-specific (heads, their geometry and hit area, the Arrow command). | Figma: "Like the line tool, you can make adjustments to the Stroke properties" ([F-SHAPE](https://help.figma.com/hc/en-us/articles/360040450133-Shape-tools)); every two-endpoint path offers all eight caps ([F-VN](https://help.figma.com/hc/en-us/articles/360040450213-Vector-networks)). |

## Conflicts resolved in this contract

1. **Drawn tool vs inline default.** Figma and Word create arrows by dragging (F-SHAPE, W-LINE); the owner's inline default (OD-INL, precedence 1) wins: insert at the caret, then drag endpoints (AR-CD-02, AR-OS-01, AR-OS-02).
2. **Stroke position.** S9 shows "Position Inside" in the Figma pane; F-STROKE says lines are centre and its table marks Position ✕ for arrows. The documented behaviour wins: centre, no Position control (AR-CD-11, AR-OS-09).
3. **Cap list.** F-VN names eight caps (including Circle arrow) while saying "six"; F-STROKE lists seven (no Circle). All eight are offered (AR-CAP-01). The branch prototype supports only None, Line arrow, Round and Square; that is a build gap, not a contract limit.
4. **Shift while drawing.** Word constrains to horizontal/vertical (W-LINE); Figma documents no line constraint. 45° steps cover both (AR-CD-05).
5. **On-canvas badge.** S9 shows "157 × 0"; OD-LBL removes canvas labels (AR-FB-01).
6. **Stroke removal and weight.** Figma allows removing a stroke and weight 0. The stroke stays mandatory (no −; the eye hides it), and weight is 0…100 as the line (coordinator decision CD-SH-11 19:05, overriding round 1's 1 px floor and the critic's CA-09 recommendation); at weight 0 heads have no size and the arrow stays reachable by the minimum hit band and Document objects (AR-CD-10).
7. **Swap semantics.** The branch proof swaps cap styles only; this contract agrees (AR-CD-12). An alternative (swap the endpoints, keeping caps) was rejected because it moves X/Y.
8. **Head sizes.** No source gives head sizes; the branch proof uses three weights per axial inset with no floor; this contract uses `max(4w, 6 px)` (AR-CD-04) so a 1 px arrow is legible. The critic should challenge the factor against Figma's in-app rendering if an official figure is found.
9. **Spec trace.** U114 describes text-bearing shapes; arrows have no text. Rows trace to U114 today; the report proposes U115 (lines and arrows) and generalising U114.P1–P3 to "shape", after which every AR row re-traces to U115 / U115.P1–P3 without changing behaviour. Print traces to U16, export to U17, import to U18 (round 1 wrongly cited U15).
10. **Line contract alignment.** Agreed with the line (committed `0d72adc`, sha 8c608f64): X/Y is the start point (LN-CD-01), Shift 45° with whole-px projection (LN-CLK-21, LN-CAN-07), hit band max(4 screen px, half the on-screen weight) and 10 × 10 handle targets (LN-SEL-22, LN-SEL-26), mandatory stroke, weight 0…100 (LN-FLD-11), H disabled 0 (LN-FLD-07), rotation zone with Shift 15° (LN-PTR-06, LN-CLK-26/27), crosshair handle cursor (LN-PTR-05), one pane and Tab order (LN-KB-03, LN-BTN-31), one accessible name (LN-KB-02), Ctrl+D keeps name and number (LN-CAN-15), Pointer Lock cases (LN-NF-35…44), swap disabled when equal, "Swap endpoint caps" (LN-BTN-18), no hover preview (LN-COL-21), insert replacing selected text and floating-selection insert at the start of the first anchor paragraph (LN-SEL-19/20), anchor under the top of the box (LN-CAN-01), pointer-capture commit (LN-CLK-18), dashes (LN-BTN-19…21, LN-FLD-12/13, LN-COL-15), Tight = Square for diagonals (LN-WP-09), one object kind, naming, Mixed, header and the eight-style selects (LN-SEL-30/31/32, LN-BTN-16/17). Deliberate difference: an object inserted by the **Arrow command** starts None / Line arrow, where the Line command starts Round / Round (LN-COL-01, LN-BTN-16): an Arrow command that inserted no arrowhead would insert a line (AR-CD-03).
11. **Coordinator decisions over critic recommendations.** Critic r1 recommended the default arrow cursor on endpoint handles (CA-06) and a 1 px weight floor (CA-09); coordinator decision CD-SH-11 19:05 chose crosshair and 0…100 for both contracts, and those are applied. CA-01's proposed AR-SEL-13 is not added because LN-SEL-31 defines Mixed across lines and arrows once (coordinator note); AR-CAP-18 references it.
12. **Rotation zone vs large heads.** At weight 10 a Circle or Diamond head reaches 20 px past the endpoint, beyond the line's 16 px rotation zone; the zone starts at the head's ink edge, so the head is never a rotate target (AR-CD-06, AR-CLK-23, AR-SEL-14).
