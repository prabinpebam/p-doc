No row's behaviour changes.

**Process** (spec, "Behaviour contract process — PERMANENT rule", 14:34). (1) **Contract**: this file. (2) **Independent completeness critic** checks it against Figma and Word section by section before any build. (3) **Build and test 1:1**: one automated test per in-scope row with the row's test ID; done only at 100 % of in-scope rows passing. (4) **Contract-blind adversarial review**; every difference becomes a new row. (5) **Owner**. Builds of this contract wait for the owner's verdict on the rectangle. Every test follows the spec's **Testing safety** rule (headless, fresh temporary profile, no visible window, no OS cursor or focus taken; Pointer Lock requested only after ~3 px and released on every exit).

**How this contract reuses the rectangle.** Where the star behaves exactly like the rectangle, a row here cites the rectangle row (`RC-…` in [rectangle-behaviour-contract.md](rectangle-behaviour-contract.md), **committed in 9095350**, 404 row IDs: the 403 of the working copies `4245F2F3` and `1AE67CB0` plus RC-OS-43, the cross-page anchoring scope freeze CD-63A0-01) instead of copying it: read "rectangle" as "star" and the cited row's expected result, source and CD apply unchanged. A **reference row** (`ST-…-REF`) names the RC rows it adopts and one test ID; that test is a parametrised suite that re-runs each named RC test against a star fixture (default star, plus a floating Square star where the RC row needs floating) and reports **one result per RC row**, so coverage stays 1:1. RC rows that do not apply to a star, or apply with a change, are named in the reference row and given full ST rows. The rectangle's numbering of IDs and test IDs is not reused: star tests are `T-ST-<suffix>`.

## Conflicts resolved in this contract

1. **Ratio wording.** Figma's help says ratio is "represented as percentage of the star's diameter"; read as inner diameter ÷ outer diameter, which equals inner ÷ outer radius, so 100 % puts the inner points on the outer ellipse (ST-CD-03).
2. **Radius handle visibility.** Figma reveals the radius handle on hover over a corner (F-CR); the rectangle contract shows dots whenever the shape is selected (its conflict 10, owner reference SS-RAD). The star follows the rectangle so all shapes look and behave alike (ST-CD-06).
3. **Alt on the radius dot.** On a rectangle Alt changes one corner (OD-RAD, F-CR); Figma states the single-corner canvas edit "only applies to rectangles", so on a star Alt changes nothing (ST-CLK-05, ST-OS-07). Figma wins for shape editing (precedence 3); no owner decision names stars.
4. **Count handle.** Figma lists Count as an on-canvas handle without documenting it; the contract keeps Count in the pane only (ST-OS-06) rather than invent a gesture.
5. **Creation.** Figma and Word both create a star by drawing (F-STAR, W-SHP); the owner's placement decision makes every new shape inline at the caret, so drawing, Shift/Alt while drawing and click-to-place are out (ST-OS-01…04) and their intents are reached on the handles.
6. **Tight on a rotated star.** Word's Tight follows the shape (W-LO); the owner rule for rotated shapes (OD-ROT) wraps the axis-aligned rotated box. The owner rule wins (precedence 1) for any rotation ≠ 0 (ST-WP-04); unrotated stars follow the outline (ST-WP-03).
7. **Dot keys vs field keys.** Radius dot keys step 10 / 100 (OD-RAD) while the pane fields step 1 / 10 (OD-NUM), as for the rectangle (its conflict 2); the ratio dot steps 1 / 10 because a percentage has no 10-unit fine step that makes sense (ST-CD-08).
8. **Field label.** The round-1 draft labelled the field "Points"; coordinator decision CD-SH-02 (19:05) uses Figma's label "Count" in both the polygon and star panes, with the accessible name "Count, number of points" (ST-CD-04).
9. **Radius units and limit.** The branch's polygon stores "Corner rounding" as 0–40 % (BRANCH); Figma measures corner radius in pixels (F-CR: "Figma represents corner radius in … pixels"), so the star's radius is px. The round-1 draft capped it at ⌊min(W,H)/2⌋ and kept values past each point's visible limit, leaving a dead range (critic STC1-05); CD-SH-01 (19:05) stores it clamped to the visible-rounding limit when the person sets it, with the dot on the arc centre, as the polygon (ST-CD-05, ST-CD-07); untouched values are kept as read and drawn clamped (CD-SH-09).
10. **Invalid saved values.** The branch's polygon throws "Polygon parameters are invalid" on out-of-range values; for stars a document always opens with values clamped and untouched stars keep their stored values (CD-SH-04, ST-CD-13, ST-WP-09), because a refused shape would block the whole document.
11. **Which points the radius rounds.** The round-1 draft rounded all 2n points. Figma's help says the radius rounds "the points of the star" and the plugin API says `cornerRadius` "controls the outer corners of the star" (F-API), so only the n outer tips are rounded and inner rounding is out (ST-CAN-06, ST-OS-08).
12. **Default size.** Figma creates a 100 × 100 star (F-API); CD-SH-03 (19:05) gives every closed shape the rectangle's 200 × 120 insert size (ST-CD-01).
13. **Names and duplicates.** The round-1 draft numbered stars "never reused" and renamed a Ctrl+D copy "Star N+1", against the adopted RC-BTN-24 / RC-CAN-25 (critic STC1-01). The rectangle rows win: N = 1 + the highest star number, a copy keeps its name and is told apart by "k of n" (ST-SEL-08, ST-CAN-13, ST-KB-01).
14. **Text overflow direction.** A word wider than the text area runs past its right edge as RC-CAN-38 says, not centred (critic STC1-08; ST-CD-10).
