# Polygon behaviour contract

Status: draft contract, 2026-10-30. Docs only; no implementation is authorised by this file. Traces to P1/P3/P4 → J3/J15 → U114, U114.P1–P3 and flows DP1–DP4 in [spec](../product/spec.md) ("Rectangle document placement addendum", whose placement, number-field, process and testing-safety rules apply to every shape). Since the spec's [shape generalisation decisions](../product/spec.md#shape-generalisation-decisions-2026-10-30-cd-63a0) (SG1, 2026-10-30), U114.P1–P3 and DP1–DP4 name every shape, so placement rows trace to them directly. Builds for this shape wait for the owner's verdict on the rectangle.

**Process.** As the [rectangle contract](rectangle-behaviour-contract.md): (1) **contract** (this file); (2) **independent completeness critic**; (3) **build and test 1:1**: one automated test per in-scope row, done only at 100 %; (4) **contract-blind adversarial review** plus an independent visual check; (5) **owner**. Out-of-scope rows are listed on purpose with a reason; nothing may be silently absent.

Spec references name the section at HEAD 039247d ("Behavior reference decisions (2026-10-30)", "Rectangle document placement addendum").

**How this contract reuses the rectangle contract.** A polygon is the rectangle's object with a different outline: same selection, pane, number fields, fill and stroke, Word placement, undo and keyboard rules. So:

- **Inherited rows.** Each section lists the RC-IDs of [rectangle-behaviour-contract.md](rectangle-behaviour-contract.md) that apply **unchanged**, reading "rectangle" as "polygon", "Insert > Rectangle" as "Insert > Polygon" and "Rectangle N" as "Polygon N". Each inherited row is still built and tested for the polygon: its test ID is `T-PG-` + the RC-ID (e.g. `T-PG-RC-PTR-02`), so it never collides with a PG row's test (`T-PG-PTR-01`). An inherited out-of-scope row stays out for the polygon for the same reason. Inheritance is against the rectangle contract **committed in 9095350** (2026-10-30; 404 row IDs: 358 in scope, 45 out, 1 withdrawn), which holds the same 403 row IDs as the working copy 1AE67CB0… counted in round 5 plus RC-OS-43 (the cross-page anchoring scope freeze CD-63A0-01, inherited as out); including RC-CAN-38/39, RC-PL-01…10 and RC-OS-42; a row added to it later is inherited by default unless the critic or a PG row says otherwise.
- **Replaced rows.** Where the polygon differs, the RC row is **not** inherited; a PG row says so in its Source column ("replaces RC-…") and is the only contract for it.
- **Not applicable.** RC rows with no polygon counterpart are listed with the PG row that explains why.
- **PG rows** are written in full. Columns as the rectangle contract, plus **Trace** (the spec user-can or flow each row serves). Scope "in" means built and tested in this slice for the reason in Trace; "out" rows give their reason in the behaviour column.

## Contract decisions to challenge (PCD)

The rectangle's CD-01…CD-14 apply unchanged (rotation sign and wrap, Mixed adds to each value, marquee out, floating-only multi-select, snapping out, one fill and one stroke, Alt+letter out, scrub Shift ×10, Enter/double-click edit text, dots hidden under 32 px, Ctrl+drag plain, inline keyboard move waits for clipboard). | PCD | Decision | Reason |
| --- | --- | --- |
| PCD-01 | **Count** (number of sides) is a whole number from 3 to 60. | F-API sets the minimum (integer ≥ 3); no Figma page states a maximum. 60 sides on a 10 000 px shape already differ from a circle by under 0.14 % of the radius, so more sides add nothing a document can show, and OD-NUM needs a max. |

| PCD-03 | **Geometry.** Vertex *i* (0…n−1) sits at angle −90° + *i* × 360°/n on the ellipse inscribed in the W × H frame (centre at the frame centre, semi-axes W/2 and H/2). The first vertex is top centre. | PCD-04 | **Corner radius** is one value in px for every corner. Its maximum (the visible-rounding limit) is the largest whole px *r* for which no two corner arcs overlap: on every edge, the two tangent lengths *r* / tan(α/2) (α = that corner's interior angle, measured in page px on the unrotated frame) add up to no more than the edge's length (computed to 0.01 px, then floored). | PCD-05 | **One radius dot**, on the axis from the first vertex to the frame centre (the first vertex's bisector, because the polygon is mirror-symmetric about the vertical centre line). | PCD-06 | **Hit area.** An unselected polygon is hit only inside its outline (fill area plus visible stroke, whether or not the fill is shown); the empty parts of its frame (e.g. the band under a triangle) pass the click to the page. | PCD-07 | **Text inside a polygon** (U114: shapes are text-bearing): native paragraphs in the **largest-area axis-aligned rectangle inscribed in the polygon's outline as drawn** (current Count, radius and flip; computed in the unrotated frame, then rotated with the polygon), wherever in the outline that rectangle lies and whatever its proportions (it is centred on the frame only when that is the largest; on a tie, the position closest to the frame centre); a flip recomputes it on the flipped outline. For a polygon the rectangle is symmetric about the vertical centre line. Inside that inscribed area the text uses the rectangle's **internal margins and alignment (RC-CAN-40**, applied by PG-CAN-14): inset left and right 9.6 px, top and bottom 4.8 px (page px, scaled by zoom, rotated and flipped with the polygon), text anchored to the **top** of the inset area, paragraph alignment per paragraph. **Each axis floors to 0 on its own** (no minimum, no auto-grow): if the inner **width** floors to 0 (area narrower than 19.2 px), the text box is a zero-width column at the area's horizontal centre x and the first line starts there at the area's top + 4.8 px, with paragraph alignment applied about x (a left-aligned line starts at x, a centred one is centred on x, a right-aligned one ends at x; RC-CAN-40, critic r7 R7-07); if the inner **height** floors to 0 (area shorter than 9.6 px), the first line's top sits at the area's vertical centre, starting at the area's left + 9.6 px; if both floor, the first line starts at the area's centre. There is no minimum size: text that does not fit overflows exactly as RC-CAN-38/39 say (W/H unchanged, wrap between words, a word wider than the area runs past its right edge, lines past the bottom drawn below, never clipped, shrunk or grown); text stays upright and readable after a flip (RC-CAN-32/33). Following the slanted edges line by line is out (PG-OS-14). |

## Conflicts resolved in this contract

The rectangle contract's conflicts 1–27 (commit 9095350) apply unchanged. Polygon-specific:

1. **Count limits.** Figma documents only the minimum (F-API, integer ≥ 3); BR-545 used 3–12. 3–60 is chosen (PCD-01): 12 is far below what Figma allows, and 60 is where more sides stop being visible.
2. **Default count.** BR-545 inserts a pentagon; Figma's polygon tool defaults to a triangle (F-PG), so the contract inserts a triangle (PCD-02).
3. **Rounding unit.** BR-545 stores "Corner rounding" as 0–40 % of each edge; Figma's Corner radius is in px for polygons too (F-CR-PG), so the contract uses one px radius with the inradius as its maximum (PCD-04). A file written by BR-545 opens with its sides and rounding mapped to Count and radius without loss (PG-CAN-13).
4. **Radius handle visibility.** Figma reveals the polygon's radius handle on hover near the corner (F-PG, F-CR-PG); the owner's rectangle reference keeps dots visible whenever selected (SS-RAD, rectangle conflict 10), so the polygon's single dot is always shown when large enough (PCD-05).
5. **Radius readout.** Figma shows the radius while hovering the handle (F-PG); OD-LBL removes every on-canvas value (PG-FB-01).
6. **Square versus Tight.** For a sharp rectangle they coincide; for a polygon Word's definitions (box versus edge) give different text flow, so both are built honestly (PCD-08, PG-WP-02/03), as spec "Rectangle document placement addendum" requires.
7. **Insert placement.** Word inserts shapes floating in front of text; the owner's inline default wins (PG-WP-08).
8. **Damaged values.** BR-545 refuses to open a document whose polygon values are out of range ("Restore a valid document version"); the contract opens it with the nearest valid values (PCD-12), because documents are never lost.
9. **Field label.** BR-545 labels the field "Sides"; Figma calls it **Count** (F-L101). The visible label is "Count" and the accessible name "Count, number of sides" (coordinator decision CD-SH-02 19:05), the same pattern as the star's "Count, number of points".
10. **Consistency with the star contract** (critic r1 CPG-04), each settled once by the coordinator and applied to both contracts: (a) radius dot on the arc centre with the arc-centre travel rule (CD-SH-01; PCD-05); (b) one maximum, the visible-rounding limit; the stored value is clamped when the polygon is edited and untouched values are kept as read (CD-SH-09); End reaches it on the focused dot only (CD-SH-08) (CD-SH-01; PCD-04); (c) visible label "Count", accessible name containing it (CD-SH-02; PG-FLD-03); (d) damaged values clamped for display, untouched objects written as read (CD-SH-04; PCD-12); (e) the rectangle's 200 × 120 default size for every closed shape (CD-SH-03; PCD-02); (f) polygon + star selections: one shared Count, Ratio only for all-star selections, no pane title on any multi-selection (CD-SH-05, star contract r2; PCD-09, PG-SEL-09).
11. **Clicks on Tight text inside a selected polygon's frame** (critic r1 CPG-08). Figma makes a selected layer's bounds draggable; Word treats text flowing into a shape's area as ordinary text. Word wins for text (precedence 2): the text gets the click (PCD-06, PG-CLK-08).
12. **Text area** (critic r1 CPG-01/02). The first draft's incircle-based area was correct only for W = H; the area is now computed from the rounded outline for any aspect (CD-SH-06; PCD-07, PG-CAN-05).
13. **One text-area rule with the star** (critic r2 CPG2-01/03/04/05; coordinator clarification 18:59). Round 2 used a vertical-search area with 8 px padding and round 3 a frame-proportioned, centred one; both are superseded. Polygon and star now share one rule, worded as the star's ST-CD-10 (r4): the largest-**area** axis-aligned rectangle inscribed in the outline as drawn, any aspect and position (ties nearest the frame centre), recomputed on flip so it moves with a flip, RC-CAN-40 margins, top-aligned, floor 0 (PCD-07, PG-CAN-14).
14. **Old-branch text position** (critic r2 CPG2-10). BR-545 centred shape text; this contract top-anchors it (RC-CAN-40), so an opened BR-545 polygon's text may move up. Decision: every polygon lays out alike (PG-CAN-13).
15. **End in the radius field** (critic r2 CPG2-02). Round 2 let End set the limit in the field; the shared field keeps Home/End for the caret (RC-KB-20, CD-SH-08); only the focused dot jumps to the limit (PCD-04).
