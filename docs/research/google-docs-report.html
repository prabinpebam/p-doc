06How it behaves

Business rules observed in the product, each with its evidence. They become the acceptance tests of the new product.

Editing, layout, review and versions 10 rules

R-001 Every change is saved automatically; Ctrl+S does nothing harmful

Given
a document open for editing
When
the writer types or presses Ctrl+S
Then
the change is saved without a dialog and the shortcut list notes "Every change is automatically saved"
Evidence: [doc SRC-001]Feature: F-036 · Screen: S-001

R-002 Headings feed the outline

Given
the outline is shown
When
text gets a Heading style
Then
it appears in the outline at its level; "Remove from outline" hides it without changing the style
Evidence: [doc SRC-008] [obs EV-002]Feature: F-022 · Screen: S-001

R-003 Pageless hides page-only elements without deleting them

Given
a document with headers, footers or page numbers
When
it switches to pageless
Then
those elements are hidden and come back when it switches back to pages; columns, page numbers, headers and footers cannot be added while pageless
Evidence: [doc SRC-005]Feature: F-016 · Screen: S-001

R-004 Page setup applies to the whole document, this section, or this section forward

Given
section breaks exist
When
the writer changes orientation in Page setup
Then
"Apply to" decides the scope; "Set as default" makes the setup the default for new documents
Evidence: [doc SRC-011]Feature: F-017 · Screen: S-002

10Build plan

What to build and in what order, the acceptance tests, and what to copy, avoid and improve.

Updated: 2026-10-28 · Status: draft

This KB feeds P-Doc, a desktop hybrid of Google Docs and Word (docs/product/spec.md). It is not a full clone: P-Doc keeps what Docs does best and drops what depends on Google's cloud.

Problem and users

A single writer (and occasional reviewer) wants Docs' calm, always-saved editing and review modes, but with files they own, offline by default, and versions they can see and restore.

BR-001 Real-time sharing needs a hosted service

  • Category: infrastructure
  • Blocks: F-040 (share, publish, approvals) and live co-editing
  • Gatekeeper: none; it needs a server the clone does not have
  • Severity: cuts feature
  • Market weight: nice to have for a single-writer desktop app
  • What it takes: a sync server with operational transforms or CRDTs, accounts and access control
  • Mitigation: share through GitHub (public repository) and review with comments and suggestions in the file
  • Evidence: [doc SRC-003] [inf Q-006]

BR-002 Google-only services

  • Category: permissioned integration
  • Blocks: smart chips that link to Google people and files, Explore, voice typing, translate
  • Gatekeeper: Google
  • Severity: cuts feature
  • Market weight: nice to have
  • What it takes: Google APIs and consent screens
  • Mitigation: keep local equivalents (date chip, spelling from the OS)
